# RIA-QN+ · 提问器能力卡

## 为什么不能只把 E 换成一串问题

上游 `E — Execution` 段的每一步都有输入契约、输出契约、判停条件和完成标准。它是一份**契约**，不是一段说明。

如果 Q 段只是一串开放式问题，agent 会在第二句就滑回「顺便把答案也说了」——因为给答案是最自然的续写。所以：

- **Q 必须带契约**（每一问的暴露目标、不代答约束、分支、完成标准）
- **N 必须单独成段**（把「不许输出什么」写成可判定的清单，而不是一句「别直接给答案」）

## 七段结构

| 段 | 名称 | 相对上游 | 要求 |
|---|---|---|---|
| R | 原文 Reading | 沿用 | ≤150 字 / 英文 ≤100 词，标出处，英文自译 |
| I | 骨架 Interpretation | 沿用 + 加一项 | 5–15 行，用自己话写；额外写清**作者想让读者自己发现什么** |
| A1 | 应用示例 | 沿用 + 加一项 | 优先书中案例；额外标注**读者在这段里通常先答错什么**；合成演练仍须如实标注 |
| A2 | 触发场景 | 沿用 + 转向 | 3–5 场景 + 中英双写语言信号 + 相邻 skill 区分；触发的是「该被提问」而不是「该给答案」；description 必须含可识别负例（L1） |
| **Q** | **提问序列 Question Ladder** | **替代 E** | 3–5 问，每问五字段，见下 |
| **N** | **禁止输出 Non-answer** | **新增** | 可判定清单，见下 |
| B | 边界 Boundary | 升级 | 从四小节附录升级为 L1–L5 结构，见 `03-boundary-five-layers.md` |

## Q 段规范

每一问写满五个字段：

| 字段 | 含义 | 硬要求 |
|---|---|---|
| `question` | 具体、可回答的问句 | 不暗示答案，不用「你是不是应该……」式反问 |
| `exposes` | 这一问要暴露的假设 / 偏差 / 被忽略的条件 | 必须指向具体内容，不能写「引发思考」 |
| `no_answer` | agent 不得在用户回应前给出答案 | 固定写 `true`；这是硬约束不是建议 |
| `branch` | 分支 | 答不出 → **最小提示**（不是结论）；答得很快 → 追问一个反例；答出但依赖未声明假设 → 打 L3 标签 |
| `done` | 完成标准 | 用户给出了什么，才算这一问过关 |

**排序原则**：具体情境 → 假设 → 反例 → 抽象权衡。不要第一问就问「你的底层假设是什么」，那会逼用户编一个答案。

**整卡完成标准**：用户能自己说出「在这个情境下我依赖了 X 假设」，并至少指出一个会让结论翻转的条件。

不是「用户表示听懂了」，也不是「对话轮次达到 5 轮」。

## N 段规范

至少覆盖这五条，每条都要能判定：

1. 不输出直接结论 / 评分 / 排名 / 「你应该……」
2. 不把作者的结论改写成通用规则
3. 不在用户回应前给出 Q 的答案
4. 不用「通常来说」「一般来说」包装隐性建议
5. 不把原书案例当作当前情境的证据

允许输出：问题、最小提示、复述用户自己的话、带出处的原文引用、边界与不确定性声明。

`config.json → interrogator.forbid_conclusion_phrasing` 给出可直接匹配的措辞样例。N 段要压缩进 frontmatter `description` 的「何时不用」，让 L1 能识别。

## 与上游 E 段的契约对照

这不是「少了执行步骤」，是「换了契约类型」：

| 上游 E | 本包 Q / N |
|---|---|
| 输入契约（必需字段、类型、单位） | 情境契约（需要用户先提供什么背景，缺了先问） |
| 输出契约（字段、格式、完成标准） | 整卡完成标准（用户自己说出假设） |
| 判停条件 | `branch`（答不出 / 太快 / 依赖未声明假设） |
| 每步完成标准 | 每问 `done` |
| 流程分支与失败处理 | `no_answer` + N 段禁止清单 |

## 提问器卡模板（正文片段）

```markdown
## R — 原文
> {{≤150 字，标出处}}
> — {{作者}}, {{章节/页码}}

## I — 方法论骨架
{{5–15 行，自己的话}}
**作者想让读者自己发现的是**：{{一句话}}

## A1 — 书中案例
- 类型与来源：{{原书亲历/转述/例题 + 定位；无则写「原书未提供，以下为合成演练」}}
- 问题/输入：
- 方法怎么被用：
- **读者在这里通常先答错什么**：
- 结论 / 结果：{{未交代则写「未说明」}}

## A2 — 触发场景
1. {{场景}}
2. {{场景}}
3. {{场景}}
语言信号：「…」/ "…"
与相邻 skill 的区分：…
**负例信号（L1）**：「…」/ "…"（命中则不激活）

## Q — 提问序列
### Q1 {{问句}}
- exposes: {{要暴露的假设}}
- no_answer: true
- branch: 答不出 → {{最小提示}}；答得快 → {{追问反例}}；依赖未声明假设 → 标 L3
- done: {{用户说了什么才算过}}

### Q2 …（共 3–5 问，按 具体→假设→反例→权衡 排序）

**整卡完成标准**：用户能说出「我依赖了 X 假设」+ 至少一个会让结论翻转的条件。

## N — 禁止输出
- {{五条以上可判定清单}}
- 允许：问题 / 最小提示 / 复述 / 带出处原文 / 边界声明

## B — 边界（L1–L5）
见 BOUNDARY.yaml；本段只写人读摘要与 author 盲点，机器判定以 yaml 为准。
```

## 常见失败模式

1. **Q 写成反问包装的建议** —「你是不是应该先看看数据？」是建议，不是问题。
2. **第一问就问抽象假设** — 用户只能编一个答案，后面全歪。
3. **N 段只有一句「不要直接给答案」** — 不可判定，等于没有。
4. **用户答不出就整段倒出原书结论** — 应给最小提示；最小提示的定义是「缩小范围但不给答案」。
5. **用合成演练冒充书中案例** — 沿用上游红线，如实标注。
6. **把 B 写成「仅供参考」** — B 必须指向 L1–L5 结构与 `BOUNDARY.yaml`。
7. **提问器自己去执行判断** — 提问器只负责让用户形成判断，不代做判断。
