# 阶段 -1 · 内容类型判定门

## 为什么必须放在最前面

上游 `cangjie-skill` 的输入要求只问四件事：文本来源、内容元信息、使用目的、是否首次试点。这四个问题都**默认产物是执行器**——「使用目的」甚至直接决定 `single` / `pack` 输出模式。

如果用户说「我想拿来日常用」，一本判断力型的书会被顺理成章地推进 single 模式，等到阶段 2 写 E 段时才发现写不出可执行步骤。那时候已经跑完三个阶段了。

所以判定要在「使用目的」之前：**内容类型决定路径，使用目的只决定包装**。

## 六个可观测信号

判定不看感觉，看原文里能指出来的东西。每条标 `A`（答案型）/ `J`（判断力型）/ `?`（无法判定），并写出处。

| # | 信号 | 答案型 A | 判断力型 J | 看哪里 |
|---|---|---|---|---|
| 1 | `conclusion_form` 结论形态 | 可复述的规则、步骤、公式，脱离语境也能照做 | 判断标准与权衡，换个情境要重新估 | 每章小结、粗体句、编号列表 |
| 2 | `argument_role` 论证的作用 ★ | 证明结论成立；删掉论证，结论仍完整 | 让读者亲历一次直觉失效；删掉论证，结论变成空洞口号 | 章节主体篇幅分布、实验/悖论段落 |
| 3 | `case_function` 案例的功能 | 示范怎么执行 | 暴露直觉通常在哪里出错 | 案例前后文的转折 |
| 4 | `failure_mode` 失效方式 ★ | 套错场景会做错事 | **直接给答案会剥夺判断力** | 作者自述局限、警告段 |
| 5 | `author_caveat` 作者自述局限 | 写清适用条件与边界 | 强调没有通用解法、取决于情境 | 序言、结论、脚注 |
| 6 | `transferability` 收益可迁移性 | 跨领域仍可照做 | 跨领域要重新权衡 | 作者给的跨域例子 |

★ = 硬信号。这两项直接决定「压成执行器会不会毁掉书的价值」。

## 判定规则

```
逐条标注 A / J / ?，? 不计入总数，但要在产物里列出
  J >= 4                      → judgment
  硬信号 2 + 4 同时为 J      → judgment（即使总分不足 4）
  A >= 4 且未触发硬信号      → answer
  其余                        → mixed（进入切分）或 undetermined
  无任何信号可判              → answer + undetermined: true
```

- **保守默认**：判不出来就走 `answer` 并标 `undetermined: true`，不要凭印象选 `judgment`。走错到执行器还有 B 段兜底，走错到提问器会把本来能直接用的方法变成一串问题。
- **阈值可调**：`config.json → content_type_gate.judgment_threshold`。
- **逐条留痕**：每个信号必须能指到章节 / 页码 / 时间戳，不能只写「感觉偏判断力」。

## 混合型怎么切

一本书里常常两种都有。**按判断单元切，不按整书投票。**

切分单元 = 一个可判定的适用条件。最小单元要能回答：「这一块在什么条件下成立？」这也是边界的切分依据——边界不是事后补的补丁，是在切的时候定下的。

切分表模板：

| unit_id | 范围（章节/时间戳） | 类型 | 判定依据 | 去向 |
|---|---|---|---|---|
| U-01 | 第 2 章 | answer | 给出可复述的三步核算口径 | 上游 RIA++ |
| U-02 | 第 4–5 章 | judgment | 用两个实验让读者体验直觉失效 | 本包 RIA-QN+ |

禁止：

- 按「多数章节哪类多」给整本书定一个类型
- 把同一章里的论证段和执行步骤混编进一张能力卡
- 为了凑满信号数，把作者的反例解读成「失败模式清单」（那仍是答案型）

## 常见误判

| 误判 | 纠正 |
|---|---|
| 「知识密度大 = 答案型」 | 密度大往往正是判断力型的特征：大量限定条件、反例、例外，而不是更多可执行步骤 |
| 「书里有 1-2-3 步骤 = 答案型」 | 作者可能用步骤演示一次思考过程，而不是给可复用流程。看 `argument_role` |
| 「能落地 = 该做执行器」 | 判断力型的落地是「更会问问题」，不是「更会照做」 |
| 「用户说想拿来用 = 答案型」 | 使用目的不改变内容类型，只改变交付包装 |
| 「作者自己给了结论 = 答案型」 | 看删掉论证后结论还剩什么；若剩一句正确的废话，是判断力型 |

## 判定之后

- `answer` → 交回上游 cangjie-skill 原七阶段，**不在上游流水线里插任何东西**；但仍须产出 `BOUNDARY.yaml` 的 L1 / L4 / L5 三层（把上游 B 段机器可读化）。
- `judgment` → 进入本包 J0–J6。
- `mixed` → 按切分表分别走两条路径，最后在 `INDEX` 层声明哪些单元是提问器，避免调用方误当执行器。
- `undetermined` → 按 answer 走，并在 `DIGEST` 显著位置标注「内容类型未判定」，留作 L5 回写线索。
