# 结构演示（不是真实蒸馏结果）

**先说清楚**：本目录下的内容全部是**格式演示**，用于说明 `CONTENT_TYPE.md`、Q 段、`BOUNDARY.yaml` 长什么样。

- 不含任何真实书籍的原文引用
- 不指向任何具体书名 / 作者 / 页码
- 不是拆书产出，不能当作方法论使用

原因很直接：上游 `cangjie-skill` 有红线「不凭记忆拆书，没文本就停下来问用户要」。本次安装没有拿到任何书的原文，所以不生成真实蒸馏产物。补上虚构的原文与页码，恰好会犯本补充包自己要防的毛病——把有条件的东西写成无条件的。

---

## 1. 内容类型判定长什么样

只示意「逐条留痕」的写法，不示意判定结果：

| 信号 | 结果 | 原文依据 | 说明 |
|---|---|---|---|
| `conclusion_form` | {{A/J/?}} | {{章节 / 页码 / 时间戳}} | {{为什么}} |
| `argument_role` ★ | {{A/J/?}} | {{…}} | {{删掉论证后结论还剩什么}} |
| `case_function` | {{A/J/?}} | {{…}} | {{…}} |
| `failure_mode` ★ | {{A/J/?}} | {{…}} | {{…}} |
| `author_caveat` | {{A/J/?}} | {{…}} | {{…}} |
| `transferability` | {{A/J/?}} | {{…}} | {{…}} |

结论行：`J 计数 n/6` · `硬信号双命中 是/否` · `判定 answer/judgment/mixed/undetermined` · `undetermined: true/false`。

真实使用时必须填满「原文依据」列。填不满就写 `?` 并标 `undetermined`，不要凭印象。

## 2. Q 段的一问长什么样

```markdown
### Q1 你手上这个情境里，两个目标分别在什么条件下会互相挤掉对方？
- exposes: 用户可能把「取舍」当成了「排序」，默认两者可同时最大化
- no_answer: true
- branch: 答不出 → 请用户只描述最近一次具体冲突（不给判断标准）；答得快 → 追问一个两者并不冲突的反例；依赖未声明假设 → 打 L3 标签
- done: 用户说出了至少一个会让偏好翻转的条件
```

注意 `branch` 里的「答不出」给的是**缩小范围的提示**，不是答案。这是提问器和执行器最容易混淆的地方。

## 3. 一条 L4 反例长什么样

```yaml
- signal: "{{用户已锁定唯一目标，只问怎么最快达成}}"
  action: do_not_apply
  redirect: "{{转向答案型执行器}}"
  source_location: "{{必填：章节 / 页码 / 时间戳}}"
```

`source_location` 不能省。没有原文定位的反例是编的，正是 L4 要防的东西。

## 4. 混合型切分长什么样

| unit_id | 范围 | 类型 | 判定依据 | 去向 |
|---|---|---|---|---|
| {{U-01}} | {{第 X 章}} | answer | {{给出可复述的核算口径}} | 上游 RIA++ |
| {{U-02}} | {{第 Y–Z 章}} | judgment | {{用实验让读者体验直觉失效}} | 本包 RIA-QN+ |

按判断单元切，不按整书投票——边界是切分依据，不是事后补丁。
